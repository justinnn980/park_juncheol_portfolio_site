Section 02
프론트/백엔드 경계에서 부딪힌 문제들
ISSUE 01
동시 접속자마다 다른 숫자가 보이는 문제 — 실시간 대결 게임
동시 변경 시 값 불일치 발생 → 서버를 단일 상태 저장소로 재설계 → WebSocket으로 결과 동시 브로드캐스트 → 전원 동일 상태 즉시 동기화
여러 사용자가 동시에 숫자를 증감시키면 기기마다 다른 값이 보였습니다. 각 기기에서 계산하면 충돌이 날 수밖에 없다고 판단해 서버만 값을 계산하고, 사용자 입력은 변경 요청으로만 전달하도록 구조를 바꿔 모든 접속자가 동일한 결과를 실시간으로 보게 만들었습니다.
ISSUE 02
화면 하나 바꾸는데 앱 심사/재배포가 필요한 문제
콘텐츠 화면 변경마다 앱 심사 대기 → React/TS 웹으로 화면 분리 → Flutter 앱에서 WebView 연동 → 배포 없이 실시간 반영
포스터가 나열되는 탐색 화면처럼 자주 바뀌는 화면을 앱 내부 화면으로 관리하면 수정할 때마다 앱 심사를 거쳐야 했습니다. 해당 화면을 React/TypeScript 웹으로 직접 분리 구현하고 WebView로 연동하는 하이브리드 구조로 전환해, 이후 콘텐츠나 배너를 앱 배포 없이 바로 반영할 수 있게 됐습니다.
ISSUE 03
웹 전환 후 첫 화면이 느려진 문제 — 지표로 증명한 개선
체감 로딩 저하 접수 → 구간별 소요 시간 측정 → 스켈레톤 UI + Lazy Loading + CDN 적용 → FCP 39%, LCP 10.8% 개선
앱 내부 화면을 웹으로 전환한 뒤 첫 화면 표시가 느려졌습니다. 감으로 판단하지 않고 로딩 구간별 소요 시간을 측정해 병목을 특정한 뒤, 화면에 보이는 콘텐츠부터 우선 로딩하고 이미지가 늦게 뜨는 구간에는 스켈레톤 화면을 먼저 보여주는 방식으로 개선했습니다.
ISSUE 04
버튼만 숨기면 안전하다고 오해하기 쉬운 권한 문제
조회 전용 계정도 URL 직접 요청 가능 → Route Handler에서 접근 직전 권한 재검증 → 서버 단 차단 구조로 재설계 → 화면 우회 접근 차단
조회 전용 계정은 화면에 등록/수정/삭제 버튼이 보이지 않지만, 주소를 직접 입력하면 요청 자체는 보낼 수 있었습니다. 화면 숨김은 보안이 아니라고 판단해 데이터 접근 직전 서버에서 한 번 더 권한을 확인하도록 구현해 실제 공격 경로를 차단했습니다.
