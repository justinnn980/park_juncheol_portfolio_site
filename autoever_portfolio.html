01 / 아우토크립트 — Microsoft 365 계정 운영 및 정책 표준화

사람마다 달랐던 입/퇴사 처리를 하나의 절차로 고정

입사자 계정 생성과 퇴사자 계정 회수가 정해진 절차 없이 담당자 손으로 처리되고 있었습니다. 절차 자체를 시스템에 넣어 누가 처리해도 같은 순서와 같은 결과가 나오게 바꿨습니다.

  • Challenge

    입/퇴사 처리 순서가 표준화되지 않아 담당자에 따라 결과가 달라지는 구조

  • Approach

    온보딩을 4단계 마법사 UI(정보입력 → 기기지급 → 계정생성 → 완료)로 표준화, 사번 자동 채번, 입/퇴사자 MS 365 계정 생성/회수 자동화, SW 라이선스 만료 자동 경고

  • Result

    기기 지급과 계정 생성이 한 흐름에서 처리되고 라이선스 만료를 사전에 파악

02 / 아우토크립트 — Teams 기반 업무 자동화

접수된 요청이 담당자에게 스스로 찾아가게 만듦

헬프데스크 요청은 MS Form으로 접수되고, 담당자는 Teams에서 일합니다. 접수와 처리가 서로 다른 곳에서 이뤄지는 게 문제라고 보고, 임직원이 이미 쓰고 있는 Teams로 요청이 바로 도착하도록 흐름을 연결했습니다.

  • Challenge

    접수 채널과 담당자가 일하는 채널이 분리되어 있는 구조

  • Approach

    MS Form 접수를 Power Automate 흐름으로 받아 Teams Webhook으로 담당자에게 자동 전달, 처리 이력 항목을 상세화

  • Result

    접수 즉시 담당자에게 전달되고 처리 이력이 남아 담당자가 바뀌어도 맥락 유지

03 / 아우토크립트 — 업무 효율화를 위한 자체 솔루션 기획/개발

아무도 요청하지 않은 엑셀 문제를 직접 시스템으로 만듦

조직도와 IT 자산 현황이 담당자 개인의 엑셀 파일 여러 개에 나뉘어 있었습니다. 파일이 복사되며 버전이 갈라지는 게 원인이라 양식을 다듬어도 반복될 구조라고 판단해, 모두가 같은 원본을 보는 웹 시스템을 요구사항 정의부터 배포까지 직접 만들었습니다.

  • Challenge

    담당자가 바뀌거나 파일을 잘못 덮어쓰면 자산 현황이 깨지는 파일 단위 관리 구조

  • Approach

    Java/Spring Boot REST API와 React 화면으로 조직도 연동 자산관리 시스템 개발, Docker/Render API로 배포 자동화

04 / 개인 프로젝트 — 생성형 AI 도구 도입 검토와 검증 기준

AI가 만든 결과물을 어디까지 믿을지 기준부터 세움

Copilot 같은 생성형 AI를 업무에 들일 때 가장 먼저 정해야 하는 것은 결과를 검증하는 방법이라고 생각합니다. 학습 Todo 관리 REST API(Study Tracker)를 Claude Code와 함께 만들면서 그 기준을 직접 세워봤습니다.

  • Challenge

    AI가 생성한 결과는 읽는 것만으로 맞는지 판단하기 어렵고, 정상 요청만 보면 문제가 드러나지 않음

  • Approach

    실패하면 안 되는 상황을 테스트로 먼저 작성하고 통과한 코드만 채택, Redis 기반 중복 요청 방지와 캐시 무효화 규칙은 직접 설계

  • Result

    단위/통합 테스트 60건, JWT 인증, GitHub Actions, Docker 구성으로 배포하고 Swagger 문서 공개
