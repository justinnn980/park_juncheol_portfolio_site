# 경동 AI/자동화(AX) 자기소개서 — 박준철

## 1. 지원동기와 직무 관련 차별화된 강점, 기여할 수 있는 점 (600자 이내)

아우토크립트에서 조직도랑 IT 자산 현황이 전부 엑셀 파일 여러 개에 흩어져 있는 걸 봤습니다. 담당자가 바뀌면 어디에 뭐가 있는지부터 다시 찾아야 하는 구조였습니다. 시켜서 한 일은 아니었는데, 이대로 두면 사람이 바뀔 때마다 똑같은 문제가 반복될 게 보여서 자산관리 시스템을 직접 만들기로 했습니다. Java/Spring Boot/React로 웹 시스템을 붙이고 실사용 데이터 2,394건을 이관했고, 헬프데스크 문의는 Teams 알림으로 바로 연결되게 했습니다. 콘텐츠 데이터 수집도 Python과 Selenium, Cron으로 자동화해서 사람이 매번 손으로 하던 일을 없앴습니다.

귀사가 코파일럿과 RPA로 업무 프로세스를 바꾸고 있는 지금 시점에, 저는 이 변화를 도구 사용법이 아니라 "어디가 비효율인지 찾아서 구조를 바꾸는 일"로 이해하고 있습니다. 요청받은 기능만 만드는 게 아니라 반복되는 수작업 자체를 발견하고 없애는 경험을 실제로 해봤고, 이걸 AI/자동화 직무에서 현업 부서 업무를 발굴하고 자동화 솔루션으로 연결하는 데 바로 쓰고 싶습니다.

## 2. 도전적 목표를 설정하고 열정을 다했던 경험 (600자 이내)

엑셀로 흩어진 자산관리를 정리해달라는 요청을 받았을 때, 처음엔 서식만 다듬어도 될 일이었습니다. 그런데 자산 항목이 306명, 1,471건 넘게 쌓여 있는 걸 보고 나서는 이걸 또 엑셀로 정리해봤자 몇 달 뒤엔 다시 엉킬 거라는 생각이 들었습니다. 그래서 목표를 서식 정리가 아니라 데이터베이스 기반 자산관리 시스템 자체 개발로 바꿨습니다.

온보딩 단계(정보입력→기기지급→계정생성→완료)를 마법사 UI로 표준화하면서 CORS 오류가 계속 나서 배포가 막혔고, 기존 엑셀 데이터를 옮기는 과정에서도 항목 누락이 자꾸 생겼습니다. 로그를 하나씩 찍어보면서 원인을 좁혀갔고, 결국 실사용 데이터 2,394건을 전부 이관해 단일 시스템으로 통합했습니다. Docker와 Render API로 배포도 자동화해서 이후엔 같은 작업을 반복하지 않아도 되게 만들었습니다. 아무도 시키지 않은 일이었지만 끝까지 밀어붙여서 완성했다는 게 지금도 제일 뿌듯한 경험입니다.

## 3. 상생의 동반자 / 스마트한 개척자 / 올곧은 전문가 (600자 이내)

저는 스마트한 개척자에 가깝다고 생각합니다. 아우토크립트에 입사했을 때 자산관리는 담당자 개인의 엑셀 파일에 의존하는 구조였습니다. 누구도 이걸 시스템으로 만들어달라고 요청하지 않았지만, 담당자가 바뀔 때마다 인수인계가 부실해지는 걸 보고 먼저 나서서 웹 시스템으로 전환했습니다.

FAQ 챗봇을 만들 때도 마찬가지였습니다. 관리자가 퇴사하거나 서버에 장애가 나면 챗봇 자체가 먹통이 될 수 있다는 걸 미리 고려해서, 챗봇보다 MS Form이 먼저 노출되도록 이중화 구조를 설계했습니다. 화려한 기능보다 실제로 문제가 터졌을 때 안 죽는 구조를 만드는 데 더 신경을 썼습니다.

시켜서 하는 일과 필요해서 하는 일은 다르다고 생각합니다. 저는 후자를 찾아서 먼저 움직이는 쪽이고, 그 결과가 엑셀 산재 관리를 없앤 자산관리 시스템과 이중화된 헬프데스크 구조로 남아 있습니다. 경동에서도 요청 이전에 비효율을 먼저 찾아내는 개척자로 일하고 싶습니다.

## 4. 전공 또는 희망직무 관련 최근 사회이슈에 대한 견해 (600자 이내)

요즘 생성형 AI가 회의록 정리나 보고서 초안 같은 사무직 업무를 대신하면서, 저연차 화이트칼라 일자리가 줄어들 거라는 이야기가 많이 나옵니다. 저는 이 변화를 사람이 없어지는 문제가 아니라, 자동화를 누가 설계하느냐의 문제로 봐야 한다고 생각합니다.

아우토크립트에서 헬프데스크 문의가 들어올 때마다 사람이 일일이 확인해서 담당자에게 전달하던 걸 Teams 알림으로 자동 연결한 적이 있습니다. 이 작업으로 없어진 건 문의를 옮겨 적는 단순 반복이었고, 담당자는 그 시간에 실제 문제 해결에 더 집중할 수 있었습니다. 자동화가 사람의 자리를 뺏은 게 아니라 사람이 해야 할 일을 더 명확하게 만든 셈입니다.

AI/자동화 직무는 이 경계를 직접 정하는 자리라고 생각합니다. 어떤 업무를 자동화 대상으로 남기고, 어떤 판단을 사람 몫으로 남길지 설계하는 역할이 앞으로 더 중요해질 거라고 봅니다.

## 전문분야 및 보유기술 (200자 이내)

엑셀에 흩어진 자산관리를 Java/Spring Boot 시스템으로 전환해 데이터 2,394건을 이관했습니다. 헬프데스크는 Power Automate와 Teams Webhook으로 Form 접수를 자동 전달했고, 입/퇴사 계정 처리도 자동화했습니다. Python/Docker 자동화와 AI 도구(Claude Code, Codex) 활용에 익숙합니다.

## 경력사항 - 아우토크립트 직무내용(상세)

엑셀 파일 여러 개로 흩어져 있던 조직도와 IT 자산 현황을 Java/Spring Boot/React 기반 자산관리 시스템으로 직접 개발해 실사용 데이터 2,394건(인원 306명/자산 1,471건)을 이관했습니다. 온보딩 절차(정보입력→기기지급→계정생성→완료)를 4단계 마법사 UI로 표준화하고 사번을 자동 채번했으며, SW 라이선스 만료 자동 경고 기능을 붙였습니다.

헬프데스크는 MS Form 접수를 Power Automate 플로우와 Teams Webhook 연동으로 담당자에게 즉시 알림이 가도록 자동화했고, FAQ 챗봇은 관리자 퇴사나 서버 장애 상황까지 고려해 챗봇보다 MS Form이 먼저 노출되는 이중화 구조로 설계했습니다. 인수인계 과정에서 정보가 누락되지 않도록 헬프데스크 처리 이력을 상세화했고, 입/퇴사자 발생 시 MS 관리자 계정 생성/회수 절차도 자동화했습니다.

SW 라이선스 관리 사내사이트를 별도로 구축했고, IT 자산 비용 절감을 위해 IDC 환경 변경과 클라우드 전환 가능성을 실사했습니다. 시스템 배포는 Docker와 Render API로 자동화했고, 이 과정에서 발생한 CORS 오류와 데이터 이관 누락 문제를 직접 원인 추적해 해결했습니다.
