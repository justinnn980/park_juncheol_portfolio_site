# 콜마그룹 2026 하반기 대졸신입 공채 — IT운영(서울) 자기소개서

## 1. 입사 전, 해당 직무수행을 위한 본인의 역량개발 노력과 입사 후, 콜마그룹에서 이루고 싶은 꿈을 설명해주세요.

아우토크립트에서 처음 맡은 일이 사내 자산관리였는데, 담당자가 바뀔 때마다 엑셀 파일이 꼬여서 어떤 노트북이 누구한테 가 있는지조차 확인이 안 되는 상태였습니다. 엑셀을 다시 정리하는 대신 데이터베이스 기반 시스템을 만들기로 하고, Spring Boot와 React를 필요한 부분만 빠르게 익혀가며 조직도와 연동되는 자산관리 사이트를 혼자 설계하고 개발했습니다. 완성한 뒤 실사용 데이터 2,394건을 옮겼고, 그 다음부터는 담당자가 바뀌어도 자산 현황이 끊기지 않게 됐습니다. SW 라이선스 관리 사이트도 같은 방식으로 이어서 만들었습니다. 문제를 발견했을 때 필요한 기술을 그때그때 채워가며 끝까지 만들어본 경험이라, 콜마그룹에서도 전산 시스템이 멈추면 안 되는 지점을 먼저 찾아 고도화하는 역할을 맡고 싶습니다. 연구모듈처럼 데이터가 끊기면 연구 일정에 바로 영향을 주는 시스템일수록 이런 방식의 운영이 필요하다고 생각합니다.

## 2. 자신이 경험했던 문제상황과, 그 문제를 해결하기 위해 몰입했던 경험을 구체적으로 기술해주세요.

홈초이스에서 서버 인프라를 맡고 있을 때, 방화벽 정책이 바뀌면서 Proxy 서버로 가는 통신이 갑자기 끊긴 적이 있었습니다. 급한 대로 다시 연결만 해둘 수도 있었지만, 정책은 또 바뀔 수 있고 그때마다 같은 장애가 반복될 거라는 생각이 들었습니다. 그래서 재연결 대신 EC2 Elastic IP를 고정해서 방화벽 규칙 자체가 IP 변경에 흔들리지 않는 구조로 다시 짰습니다. 로그를 하나씩 짚어가며 어느 시점에 어떤 IP로 통신이 막히는지 확인하는 데만도 시간이 꽤 걸렸는데, 원인을 애매하게 남겨두면 서비스 이용자가 늘었을 때 더 크게 터질 거라 생각해서 끝까지 붙잡았습니다. 구조를 바꾼 뒤로는 같은 장애가 다시 생기지 않았고, 이 김에 SSL 인증서를 적용해서 전 구간을 HTTPS로 바꾸는 작업까지 같이 끝냈습니다. 증상만 지우는 게 아니라 원인이 되는 구조까지 고치는 게 맞다고 생각한 경험이었습니다.

## 3. 다른 사람들이나 소속한 팀을 위한 활동 중, 자신만의 원칙과 계획을 세워 목표를 성취한 경험에 대해 기술해 주세요.

아우토크립트에서 헬프데스크 문의가 Form으로 들어오면 담당자가 일일이 확인하고 회신하는 구조였는데, 담당자가 자리를 비우면 그 사이 문의가 그대로 쌓였습니다. 저는 사용자 입장에서는 담당자가 있든 없든 답을 받을 수 있어야 한다는 게 맞다고 봤고, 그걸 원칙으로 두고 두 가지를 같이 준비했습니다. 하나는 Form 접수를 Teams 알림으로 바로 연동해서 담당자가 확인을 놓치지 않게 하는 것이었고, 다른 하나는 자주 묻는 질문에 먼저 안내가 나가는 FAQ 챗봇을 만들어서 담당자 계정을 이중화해두는 것이었습니다. 관리자 계정 하나에 문제가 생겨도 다른 계정으로 챗봇이 계속 응답하도록 설계했습니다. 여기에 헬프데스크 처리 이력도 상세하게 남기도록 바꿔서, 다음 담당자가 인수인계를 받을 때 예전 문의 내용을 바로 찾아볼 수 있게 했습니다. 사람 한 명에게 기대는 구조를 없애는 게 목표였고, 실제로 담당자 공백 상황에서도 안내가 끊기지 않았습니다.

## 4. 다른 사람들과 협업하여 팀 목표를 달성한 경험과 해당 과정에서 본인이 수행했던 역할과 노력을 기술해 주세요.

홈초이스에서 LG헬로비전과 딜라이브 두 파트너사에 앱을 이관하는 프로젝트를 맡았을 때, DRM을 어떻게 붙일지를 두고 파트너사 쪽과 계속 의견을 맞춰야 했습니다. 기존 플레이어를 커스터마이징해서 붙이는 방법과 검증된 DRM 솔루션을 새로 도입하는 방법, 두 가지를 놓고 검토했는데 커스터마이징은 비용은 적지만 파트너사마다 재생 환경이 달라 안정성을 장담하기 어려웠고, 솔루션 도입은 검증은 되어 있지만 일정이 더 걸리는 문제가 있었습니다. 저는 두 파트너사의 요구사항을 먼저 정리해서 공통으로 맞출 수 있는 부분과 개별로 대응해야 하는 부분을 나눴고, 그 기준으로 어느 쪽을 택할지 파트너사 담당자들과 맞춰가며 결정했습니다. 제가 실제 구현과 테스트를 맡아 진행했고, 두 파트너사 모두 오류 없이 마이그레이션을 마쳤습니다. 기술적으로 더 나은 답을 고르는 것보다 상대방이 처한 조건에 맞는 답을 고르는 게 더 중요하다는 걸 배운 프로젝트였습니다.

## 5. 기존의 것을 개선하기 위해 주도적으로 노력한 경험을 구체적으로 기술해주세요.

아우토크립트에서 자산관리 시스템을 운영하던 중에 특정 화면에서만 가끔 CORS 오류가 나고, 일부 데이터가 이관되다 만 채로 남는 문제가 있었습니다. 새로고침하면 다시 정상적으로 동작해서 그냥 넘어갈 수도 있는 문제였지만, 원인을 모르는 채로 두면 사용하는 사람이 늘었을 때 더 자주 터질 거라고 판단했습니다. 문제는 오류가 간헐적으로만 재현돼서 어디서 막히는지 특정하기가 쉽지 않았다는 점이었습니다. 그래서 오류가 날 때마다 요청과 응답 헤더를 하나씩 저장해두고, 이관 로그와 시간 순서를 맞춰 비교하는 방식으로 범위를 좁혀갔습니다. 며칠에 걸쳐 화면별로 조건을 하나씩 지워가다가 특정 API 경로와 특정 조건이 겹칠 때만 오류가 난다는 걸 찾아냈고, 그 조건을 고쳐서 이후로는 같은 오류가 재발하지 않았습니다. 증상이 가끔만 보인다고 넘기지 않고 끝까지 원인을 좁혀본 경험입니다.
