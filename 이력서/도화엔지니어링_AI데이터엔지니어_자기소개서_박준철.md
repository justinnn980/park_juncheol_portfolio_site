# 도화엔지니어링 2027년도 대졸 신입사원 공개채용 — 연구원(AI/데이터 엔지니어) 자기소개서

## 1. 우리 회사에 지원하게 된 동기를 기술하여 주십시오.

토목설계플랫폼 DIDAS 소개를 보면서 제일 먼저 든 생각은, 설계 자체보다 그 설계를 만드는 과정을 데이터로 다루는 일이 저한테 더 익숙한 영역이라는 거였습니다. 저는 엑셀 파일 여러 개에 흩어져 있던 조직도와 자산 현황을 보고 아무도 시키지 않았는데 Java/Spring Boot/React로 자산관리 시스템을 직접 만든 적이 있고, 홈초이스에서는 외부 사이트의 영화 메타데이터를 사람이 매번 확인해서 올리던 걸 Python/Selenium/Docker/Cron으로 자동화해 수작업을 없앴습니다. 두 경우 모두 공통점은 사람이 반복해서 하던 데이터 작업을 구조로 바꿔서 없앴다는 겁니다. 도화엔지니어링은 인프라 설계라는 전통적인 영역에 BIM과 AI를 결합해서 그 데이터 흐름 자체를 플랫폼으로 만들고 있다는 점이 다른 공고보다 구체적으로 와닿았습니다. 설계 데이터가 쌓이고 그걸 다시 설계에 활용하는 구조를 만드는 일에, 제가 해왔던 자동화와 데이터 파이프라인 경험을 그대로 옮겨서 기여할 수 있을 거라고 생각해서 지원했습니다.

## 2. 우리 회사 핵심 가치(인본·화합·창의) 중 가장 중요하다고 생각하는 가치를 선택하고, 그 이유와 관련된 구체적인 경험을 기술하여 주십시오.

도화엔지니어링의 핵심가치 중에서는 창의가 제일 와닿습니다. 아우토크립트에서 그린맨파워 파견으로 일할 때, 조직도와 IT 자산 현황이 담당자 개인의 엑셀 파일 여러 개에 나뉘어 있었습니다. 아무도 저한테 이걸 고치라고 한 적은 없었고, 엑셀 양식을 통일하고 입력 규칙만 다시 정리해도 당장의 불편은 줄어드는 상황이었습니다. 그런데 양식을 아무리 정리해도 담당자가 바뀌거나 파일을 잘못 덮어쓰면 똑같은 문제가 반복될 거라는 게 보였습니다. 그래서 엑셀 정리 대신 Java/Spring Boot/React로 자산관리 시스템을 직접 만들기로 했습니다. 온보딩 과정(정보입력→기기지급→계정생성→완료)을 4단계 마법사 UI로 표준화하고 사번도 자동으로 채번되게 했고, SW 라이선스 만료는 따로 확인하지 않아도 자동으로 경고가 뜨게 붙였습니다. 결과적으로 실사용 데이터 2,394건(인원 306명, 자산 1,471건)을 전량 이관했고, 그 뒤로는 담당자가 바뀌어도 같은 문제가 재발하지 않았습니다. 요청받은 일만 하기보다, 반복될 문제를 구조로 없애는 쪽을 택하는 게 저한테는 창의에 더 가깝습니다.

## 3. 본인의 성장과정 및 성격의 장단점에 대하여 자유롭게 기술하여 주십시오.

대전대학교에서 컴퓨터공학을 전공하면서 모빌리티AI/SW융합전공을 복수전공으로 함께 들었는데, 수업만으로는 부족하다는 생각에 따릉이 공공데이터로 이용량을 예측해보거나 YOLOv5로 낙상 감지 시스템을 만들어보는 식으로 혼자 데이터를 다뤄보는 걸 좋아했습니다. 장점은 문제가 생기면 증상만 없애고 넘어가지 않고 원인을 끝까지 따라간다는 겁니다. 홈초이스에서 앱과 서버 통신이 갑자기 끊기는 장애가 있었는데, 재연결 처리로 당장 덮어둘 수도 있었지만 Proxy 서버의 IP 변경 이력을 끝까지 추적해서 EC2 Elastic IP를 고정하는 구조로 바꿔 아예 재발하지 않게 만들었습니다. 그런데 이게 단점으로도 이어져서, 원인을 완전히 이해하기 전까지는 일단 넘어가질 못하는 편입니다. 급하게 처리해야 하는 일인데도 구조부터 다 들여다보려다 시간이 오래 걸린 적이 있었고, 요즘은 지금 당장 막아야 하는 부분과 나중에 구조로 고칠 부분을 먼저 나눠서, 급한 쪽을 처리한 다음에 원인을 추적하는 순서로 바꿔가고 있습니다.

## 4. 지원 직무와 관련된 경험에 대하여 기술하여 주십시오.

홈초이스에서 오초이스 앱에 들어가는 영화/콘텐츠 메타데이터를 키노라이츠 같은 외부 사이트에서 가져와야 했는데, 처음에는 담당자가 사이트를 직접 보면서 바뀐 정보를 수동으로 입력하는 방식이었습니다. 콘텐츠 수가 늘어나면서 이 방식으로는 담당자가 매번 확인해야 할 양이 계속 늘어나는 구조였습니다. 저는 두 가지를 검토했습니다. 하나는 입력 화면에 자동완성이나 템플릿을 넣어서 수작업 속도만 높이는 방법이었고, 다른 하나는 크롤링으로 수집 자체를 자동화하는 방법이었습니다. 전자는 사람이 계속 붙어있어야 한다는 전제가 그대로 남아서 콘텐츠가 더 늘어나면 다시 느려질 게 뻔했고, 후자는 초기 구축 비용이 더 들지만 한 번 만들어두면 사람이 빠져도 유지된다고 판단해서 후자를 택했습니다. Python과 Selenium으로 크롤링 로직을 짜고 Docker로 패키징해서 Cron으로 주기 실행되게 만들었습니다. 그 뒤로는 담당자가 사이트를 직접 들여다보지 않아도 메타데이터가 알아서 갱신됐고, 저는 이 경험으로 데이터를 가져오는 일은 사람이 반복하는 게 아니라 한 번 제대로 설계해서 자동으로 돌게 만드는 게 맞다는 기준을 갖게 됐습니다.

## 5. 입사 후 본인과 회사에서 이루고 싶은 목표에 대하여 기술하여 주십시오.

입사 후에는 DIDAS 같은 토목설계플랫폼에 쌓이는 설계 데이터를 다루는 일부터 빠르게 제 몫으로 만들고 싶습니다. 제가 해왔던 일은 결국 사람이 반복하던 데이터 작업(자산관리, 메타데이터 수집, 헬프데스크 접수)을 구조로 바꿔서 자동으로 돌게 만드는 것이었는데, 설계 데이터도 쌓이기만 하고 활용되지 않으면 의미가 없다고 생각합니다. 먼저는 플랫폼에 쌓인 데이터가 실제로 어떻게 설계 업무에 다시 쓰이는지를 파악하고, 그 과정에서 사람이 반복해서 확인하거나 옮기는 부분이 있다면 그걸 먼저 자동화 과제로 제안해보고 싶습니다. 이후에는 BIM/AI 설계기술 연구개발에서 나오는 데이터를 실제 운영 환경에 붙이는 역할까지 맡아서, 연구와 현업 사이에서 데이터가 끊기지 않고 흐르게 만드는 사람이 되는 게 목표입니다. 아우토크립트와 홈초이스에서 그래왔듯, 시키는 일만 하기보다 먼저 문제를 찾아서 구조를 바꾸는 방식으로 도화엔지니어링의 디지털 전환에 실질적으로 기여하고 싶습니다.
