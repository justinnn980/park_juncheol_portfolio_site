## 아우토크립트 — IT 인프라 및 자산관리 담당

자동차 소프트웨어 보안 분야 코스닥 상장기업의 사내 IT 인프라와 자산 전반을 담당하고 있습니다.

- **'조직도/IT 자산관리 시스템' 기획/개발/배포 (단독 진행)** : 조직도/HW 자산/SW 라이선스가 엑셀 파일 등으로 흩어져 관리되며 데이터가 중복/누락되고 최신 현황 파악이 어렵다는 문제를 발견했습니다. 이를 해결하기 위해 백엔드(Java/Spring Boot/PostgreSQL)와 프론트엔드(React/TypeScript)로 웹 시스템을 기획부터 개발, 배포까지 단독으로 진행했습니다. 실사용 데이터(직원 306명, HW 자산 1,471건, SW 라이선스 617건)를 연동해 조직도/HW 자산(노트북/모니터 등)/SW 라이선스(JetBrains, Microsoft 365 등)를 한 곳에서 관리하고, 만료 임박 라이선스를 자동 경고하는 대시보드를 구현했습니다.
- **온보딩 프로세스 표준화 (4단계 마법사 UI)** : 실제 온보딩 절차(기본정보 입력 → 노트북/모니터 지급 → 계정 생성 → 완료)를 반영한 단계형 UI를 설계했습니다. 사번은 담당자가 입력하지 않고 완료 시점에 시스템이 자동으로 채번하도록 만들어 기존 데이터와의 정합성을 확보했습니다.
- **배포/인프라 자동화** : Docker 멀티스테이지 빌드로 프론트/백엔드를 하나의 이미지로 통합해 Same-Origin 구조로 전환, CORS 이슈를 구조적으로 제거했습니다. Render.com REST API를 직접 호출해 DB 프로비저닝부터 배포까지 전 과정을 코드 기반으로 자동화했고, Spring Security로 외부 접근을 차단했습니다.
- **실데이터 무손실 마이그레이션** : 로컬의 실사용 데이터를 운영 DB로 이관하는 과정에서, 서버 API의 페이지 크기 상한(200건)을 인지하지 못해 일부 데이터가 누락되는 문제를 발견했습니다. 전체 페이지를 순회하는 스크립트로 재작성해 최종 100% 이관을 검증했습니다.
- **헬프데스크 Form 접수 → Teams 알림 자동화** : IT 이슈가 메일/구두로 접수되어 처리가 누락/지연되던 문제를, MS Form 접수 표준화 + 접수 즉시 담당 엔지니어에게 Teams 알림이 전달되는 구조로 개선해 대응 속도를 높였습니다.
- **채팅방/FAQ 사이트 개발 (담당자 변경/서버 장애 대비)** : 반복적으로 들어오는 단순 문의에 먼저 대응할 수 있도록 채팅방과 FAQ 사이트를 만들었습니다. 특정 담당자 개인 계정에 의존하면 그 사람이 퇴사했을 때 서비스가 멈출 수 있다고 판단해, 회사 공용 관리자 계정으로 운영되도록 구성했습니다. 또한 채팅방/FAQ 사이트에 문제가 생기더라도 문의가 끊기지 않도록 MS Form을 가장 먼저 보이게 만들어 두었습니다.
- **인수인계 프로세스 개선** : 처리 결과 위주였던 인수인계 자료에 증상/원인/조치를 상세히 남기도록 개선해, 동일 장애 재발 시 신속하게 대처할 수 있는 환경을 만들었습니다.
- **IT 자산 비용 절감을 위한 IDC 환경 변경 및 클라우드 전환 실사화** : IDC 운영 비용 구조를 분석해 클라우드 전환 시 비용 효율을 검토, 인프라 투자 계획 수립에 필요한 데이터를 정리했습니다.

**트러블슈팅 사례**

| 문제 | 원인 분석 | 해결 |
|---|---|---|
| 상태변경 API에서만 간헐적 CORS 오류 | Vite 프록시가 브라우저의 실제 Origin 헤더를 다른 포트의 백엔드로 그대로 전달 → Spring의 기본 Origin 검증 로직이 거부 | Vite 프록시에서 Origin/Referer 헤더 제거 후 포워딩 |
| React 자동완성 컴포넌트에서 선택 값이 즉시 원복 | `<label>` 내부 클릭이 리렌더링된 새 DOM 요소로 재포워딩되는 브라우저 동작과 React 상태 갱신 타이밍 충돌 | Playwright로 재현 후 `onClick` → `onMouseDown + preventDefault`로 전환 |
| Lombok 어노테이션 처리 실패로 빌드 불가 | Maven이 JDK 26을 기본 사용, Lombok과 버전 비호환 | JAVA_HOME을 JDK 21로 명시 고정 |
| 대량 데이터 마이그레이션 시 일부 누락 | 서버 API 페이지 크기 상한(200건)을 인지하지 못하고 단일 요청으로 처리 시도 | 전체 페이지 순회 스크립트로 재작성, 100% 이관 검증 |

## (주)홈초이스 — 서버/네트워크 인프라 운영 및 OTT 앱 개발
**기간** : 2024.02 ~ 2025.11 (1년 10개월)

전국 디지털케이블TV 가입가구에 VOD를 공급하는 국내 유일 사업자에서, AWS EC2/S3/Elastic Beanstalk 기반 인프라 운영과 Flutter 기반 OTT 앱 '오초이스'의 개발/운영을 함께 담당했습니다.

- **통신 장애 근본 해결** : 로드밸런싱 환경에서 Proxy 서버 IP 변경으로 방화벽 정책에 막혀 앱-서버 통신이 두절되는 장애를, 우회가 아닌 EC2 Elastic IP 할당 구조로 재구성해 근본 해결.
- **통신 구간 보안 전환** : 미암호화 중계 서버 구간에 SSL 인증서를 적용해 전 구간 HTTPS로 전환.
- **복수 사업자 앱 전환 프로젝트 2건 주도** : 매출 3,500억 규모 딜라이브(모바일TV), 가입자 343만 명 규모 LG헬로비전(헬로tv)을 오초이스 앱으로 전환. 딜라이브는 서로 다른 두 영상 보호 방식(NCG/Multi DRM)을 단일 재생 구조로 통합, LG헬로비전은 변경 잦은 화면을 웹 기반으로 분리해 앱 재배포 없이 즉시 반영되는 구조로 전환. 초기 로딩 지연은 리소스 경량화/이미지 CDN/스켈레톤 UI로 해결해 FCP 39%, LCP 10.8% 개선.
- **반복 업무 자동화** : 콘텐츠 메타데이터 수집을 Python/Selenium/Docker/Cron Job으로 자동화, 장애 대응 절차와 인프라 변경 내역을 문서화해 팀 내 공유.
- **Flutter 2→3 업그레이드** : 라이브러리 호환성 문제를 항목별 전수 점검해 서비스 중단/기능 손실 없이 완료.
