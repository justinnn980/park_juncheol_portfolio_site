Section 02
실서비스에서 해결한 문제들
PROBLEM 01
앱-서버 통신 두절 — 임시 우회 대신 근본 원인 추적
통신 장애 접수 → Proxy 서버 IP 변경 이력 확인 → EC2 Elastic IP 고정 구조 재구성 → 재발 방지 구조 확보
로드밸런싱 환경에서 Proxy 서버 IP가 바뀌며 방화벽에 막혀 통신이 끊기는 장애가 발생했습니다. 임시 재연결이 아니라 IP가 다시 바뀌어도 재발하지 않는 구조로 근본적으로 정리하고, SSL 인증서 적용으로 전 구간 HTTPS 전환을 완료했습니다.
PROBLEM 02
첫 화면 표시 지연 — 수치로 원인을 증명하고 개선
체감 속도 저하 접수 → 로딩 구간별 소요 시간 측정 → 불필요 리소스 정리 + 우선순위 로딩 → 표시 속도 39% 단축
감으로 판단하지 않고 구간별로 걸리는 시간을 측정해 병목 지점을 특정한 뒤 개선해 수치로 검증된 결과를 만들었습니다.
PROBLEM 03
NCG DRM → Multi DRM 전환 — 단일 플레이어로 통합
서비스마다 다른 DRM 방식 → 단일 플레이어 인터페이스 설계 → 라이선스 검증 흐름 통합 → 서비스 무관 동일 사용자 경험
딜라이브 앱(NCG DRM)과 헬로tv 앱(Multi DRM: Widevine/FairPlay)의 DRM 방식이 달라 동일 플레이어로 통합이 어려운 문제를 DRM 방식을 추상화한 단일 플레이어 인터페이스로 해결했습니다.
PROBLEM 04
WebView + JS Bridge — 앱 재배포 없이 즉시 반영되는 운영 구조
앱 배포 주기 의존 + 초기 로딩 지연 → 탐색 화면 WebView 분리 → JS Bridge 양방향 통신 설계 → 심사 없이 즉시 반영 운영 구조
콘텐츠 변경이 앱 배포/스토어 심사 주기에 매번 묶이는 문제를, React/TypeScript로 화면을 분리하고 Flutter ↔ WebView JavaScript Bridge 양방향 통신 구조를 설계해 앱 재배포 없이 즉시 반영되도록 바꿨습니다.
변경 전
화면 변경 → 앱 코드 수정 → 빌드 → 스토어 심사(1~3일) → 배포
변경 후
화면 변경 → 웹 배포 → 즉시 반영 (앱 배포 없음)
