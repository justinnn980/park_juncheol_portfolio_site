Section 02
직접 발굴하고 해결한 자동화 문제들
PROBLEM 01
엑셀 산재 자산관리 — 서식 정리가 아니라 시스템 자체 개발로 전환
엑셀 파일 여러 개로 흩어진 자산관리 → Java/Spring Boot/React 시스템 개발 → CORS 오류/데이터 누락 원인 추적 → 실사용 데이터 2,394건 전량 이관
담당자 개인의 엑셀 파일에 의존하던 조직도/자산 현황을 데이터베이스 기반 웹 시스템으로 직접 전환했습니다. 온보딩(정보입력→기기지급→계정생성→완료)을 4단계 마법사 UI로 표준화하고 사번을 자동 채번했으며, SW 라이선스 만료 자동 경고 기능도 붙였습니다.
PROBLEM 02
헬프데스크 처리 지연 — Power Automate와 Webhook으로 알림 자동화
Form 접수 후 수동 확인/전달 → Power Automate 플로우 + Teams Webhook → 담당자 자동 전달, 반복 확인 제거
헬프데스크 문의가 들어올 때마다 사람이 옮겨 적던 과정을 Power Automate와 Teams Webhook 연동으로 자동화했습니다. 없어진 건 단순 반복이었고, 담당자는 실제 문제 해결에 더 집중할 수 있게 됐습니다.
PROBLEM 03
FAQ 챗봇 장애 리스크 — 이중화 구조로 예방 설계
관리자 퇴사/서버 장애 가능성 → MS Form 우선 노출 이중화 설계 → 장애 상황에도 접수 유지
AI 도구로 FAQ 챗봇을 개발하면서, 관리자가 퇴사하거나 서버에 장애가 생기면 챗봇 자체가 먹통이 될 수 있다는 점을 미리 고려했습니다. 챗봇보다 MS Form이 먼저 노출되는 이중화 구조로 설계해 오류가 적은 접수 경로를 항상 남겨뒀습니다.
PROBLEM 04
앱-서버 통신 두절(홈초이스) — 임시 우회 대신 근본 원인 추적
통신 장애 접수 → Proxy 서버 IP 변경 이력 확인 → EC2 Elastic IP 고정 구조 재구성 → 재발 방지 구조 확보
Proxy 서버 IP가 바뀌며 방화벽에 막혀 통신이 끊기는 장애를 임시 재연결이 아니라 재발하지 않는 구조로 근본적으로 정리했습니다. 증상만 없애지 않고 원인을 끝까지 좁혀가는 방식은 자동화 과제를 발굴할 때도 동일하게 적용하고 있습니다.
