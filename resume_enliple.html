Section 02
이슈를 어떻게 접수하고 해결했나
ISSUE 01
쇼츠 화면 사운드 중복 재생 — 접수 후 근본 원인까지 추적
이슈 접수 → 플레이어 중복 초기화 원인 확인 → 라이브러리 생명주기 수정 → 재발 0건
쇼츠형 화면에서 영상을 빠르게 넘기면 이전 영상 소리가 겹쳐 들리는 문제가 접수됐습니다. 단순 재부팅 안내로 덮지 않고 플레이어 라이브러리의 생성/재생/종료 시점을 직접 분리하는 구조로 수정해 근본적으로 해결했습니다.
ISSUE 02
서버 통신 두절 장애 — 임시 우회 대신 근본 원인 추적
통신 장애 접수 → Proxy IP 변경 / 방화벽 차단 확인 → Elastic IP 고정 + HTTPS 전환 → 재발 방지 구조 확보
중계 서버 IP 변경으로 방화벽에 막혀 앱-서버 통신이 끊기는 장애가 발생했습니다. 임시 우회가 아닌 근본 원인을 추적해 고정 IP 할당과 전 구간 HTTPS 전환으로 동일 장애가 재발하지 않도록 구조를 개선했습니다.
ISSUE 03
웹 전환 후 초기 로딩 지연 — 지표로 병목을 증명하고 개선
체감 속도 저하 접수 → FCP/LCP 지표 분석 → Lazy Loading / 스켈레톤 UI / CDN → FCP −39%, LCP −10.8%
콘텐츠 화면을 웹으로 전환한 직후 첫 화면 표시 속도가 느려졌다는 피드백을 받았습니다. 감으로 판단하지 않고 FCP/LCP 지표로 병목 구간을 특정한 뒤 개선 조치를 적용해 수치로 검증된 개선을 만들었습니다.
ISSUE 04
경쟁 서비스 벤치마킹 — 반복 리서치 업무를 자동화
수작업 리서치 반복 확인 → Selenium 크롤링 로직 설계 → Cron Job 자동 실행 → 리서치 업무 100% 자동화
경쟁 OTT 서비스의 콘텐츠 순위/장르/히트수를 수작업으로 확인하던 방식에서 벗어나, 자동 수집 파이프라인을 직접 구축했습니다. 매일 1회 자동 실행되어 별도 조작 없이 최신 벤치마킹 데이터가 쌓이도록 만들었습니다.
