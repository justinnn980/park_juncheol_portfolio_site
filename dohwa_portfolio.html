01 / 아우토크립트 — 엑셀 산재 데이터의 시스템 전환

요청받지 않은 문제를 찾아 자산관리 시스템을 직접 구축

조직도와 IT 자산 현황이 담당자 개인의 엑셀 파일 여러 개에 나뉘어 있었습니다. 양식만 정리해도 당장은 편해지지만 담당자가 바뀌면 같은 문제가 반복될 거라고 판단해 시스템 자체를 새로 만들기로 했습니다.

  • Challenge

    담당자 개인의 엑셀 파일에 의존해 조직도/자산 현황이 관리되어, 담당자가 바뀌거나 파일이 꼬이면 데이터가 깨지는 구조

  • Approach

    Java/Spring Boot/React로 자산관리 시스템을 직접 개발, 온보딩 절차를 4단계 마법사 UI로 표준화하고 사번 자동 채번/SW 라이선스 만료 자동 경고 기능 추가

  • Result

    실사용 데이터 2,394건(인원 306명/자산 1,471건)을 전량 이관, 이후 담당자가 바뀌어도 데이터 구조가 깨지지 않는 상태로 운영

Java / Spring Boot React 데이터 이관 설계
kinolights-crawler
$ docker run --rm kinolights-crawler \
  --schedule "cron" --target "kinolights.com"
→ Selenium 세션 시작, 콘텐츠 메타데이터 수집
→ 이전 결과와 비교해 신규/변경 항목 탐지
→ 매일 자동 실행 후 컨테이너 종료 (사람 개입 없음)
02 / (주)홈초이스 — 콘텐츠 메타데이터 자동 수집 파이프라인

수작업 확인 대신 자동으로 돌아가는 수집 구조를 택함

키노라이츠 같은 외부 사이트의 영화/콘텐츠 메타데이터를 담당자가 직접 확인해서 입력하던 방식이 콘텐츠 수가 늘수록 감당이 안 되는 구조라, 입력을 보조하는 방법과 수집 자체를 자동화하는 방법을 두고 후자를 택했습니다.

  • Challenge

    콘텐츠가 늘어날수록 담당자가 매번 확인해야 할 메타데이터 양이 함께 늘어나는 구조

  • Approach

    Python/Selenium으로 크롤링 로직을 작성하고 Docker로 패키징, Cron으로 주기 실행되도록 구성해 수집부터 비교까지 자동화

  • Result

    담당자가 사이트를 직접 확인하지 않아도 메타데이터가 자동으로 갱신되는 구조로 전환, 반복 확인 작업 제거

Python / Selenium Docker / Cron 데이터 파이프라인
