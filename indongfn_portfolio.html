01 / 아우토크립트 — 사내 업무 시스템 프론트/백엔드 개발

담당자마다 따로 쓰던 엑셀을 모두가 같은 원본을 보는 시스템으로 바꿈

조직도와 IT 자산 현황이 담당자마다 다른 엑셀 파일에 나뉘어 있어 같은 자산이 파일마다 다르게 적혀 있었습니다. 양식을 통일해도 각자 복사해 쓰는 방식이 그대로면 다시 어긋난다고 판단해, 화면과 서버, DB를 직접 설계해 웹 시스템으로 만들었습니다.

  • Challenge

    파일을 복사해 쓰는 구조라 누가 언제 고쳤는지 남지 않고, 덮어쓰면 현황이 깨지는 상태

  • Approach

    Java/Spring Boot REST API와 React 화면, MySQL 테이블을 단독 설계/개발. 입사자 처리를 정보입력 → 기기지급 → 계정생성 → 완료 4단계 화면으로 묶고 사번 자동 채번, SW 라이선스 만료 자동 경고 기능 추가

  • Result

    실사용 데이터 2,394건 이관. 배포 후 발생한 CORS 오류와 이관 누락은 요청/응답 로그로 추적해 해결

02 / (주)홈초이스 — Spring Boot API 서버 / 배치 개발 및 운영

사람이 순서대로 처리하던 콘텐츠 발행을 배치로 넘김

OTT 서비스 오초이스의 콘텐츠는 발행, 인코딩, 배포를 사람이 단계마다 확인하며 넘기고 있었습니다. Spring Boot REST API 서버를 개발하고, 단계별 작업을 Quartz 배치 잡으로 나눠 DB 상태를 보고 다음 단계로 넘어가게 했습니다.

  • Challenge

    단계마다 사람이 확인해 넘기는 구조라 처리 시점이 담당자 일정에 묶여 있는 상태

  • Approach

    Quartz 5분 주기 배치 잡 6개 구성, AWS S3/Ateme 인코딩 연동, 파트너사(SO)별 인증 서버 구조를 설정으로 분리, 요청/응답 AES 암호화 적용

  • Result

    콘텐츠 발행부터 배포까지 자동화, 1년 10개월 동안 실서비스로 운영하며 기능 개선

03 / (주)홈초이스 — 서버 운영 / 장애 대응

재연결로 넘어가던 통신 장애를 구조를 바꿔 끝냄

서버와 외부 시스템 사이 통신이 갑자기 끊기는 일이 반복됐습니다. 다시 연결하면 바로 복구됐지만, 원인을 모른 채 넘기면 같은 장애가 또 생긴다고 봤습니다.

  • Challenge

    복구는 되지만 원인이 확인되지 않아 같은 장애가 되풀이되는 상태

  • Approach

    방화벽 기록을 시간순으로 추적해 중계 서버 IP 변경이 원인임을 확인. 바뀐 주소를 매번 다시 등록하는 대신 EC2 Elastic IP로 주소를 고정하고 SSL을 적용하는 구조로 재구성

  • Result

    IP가 바뀔 일이 없어져 방화벽 정책과 어긋나는 상황 자체가 사라짐

AWS EC2 / Elastic IP Linux 방화벽 정책 SSL

04 / 개인 프로젝트 — 외부 인터페이스 연동 구조

보내는 것보다 실패했을 때 다시 보내는 구조를 먼저 만듦

외부 시스템이 SAP OData API로 주문을 전송하는 상황을 Mock SAP 서버로 재현했습니다. 연동은 상대 시스템이 응답하지 않는 순간이 반드시 오기 때문에, 호출 성공보다 실패한 건을 잃지 않는 구조에 시간을 썼습니다.

  • Challenge

    전송이 실패하면 어떤 주문이 빠졌는지 알 수 없고 다시 보낼 방법도 없는 단순 호출 구조

  • Approach

    Spring Boot/Spring Data JPA로 전송 서비스를 만들고 실패 건을 PostgreSQL에 로그로 저장, 재처리 API와 전송 현황 모니터링을 구현. Docker Compose로 두 서버와 DB를 함께 기동

  • Result

    실패한 전송을 건별로 확인하고 다시 보낼 수 있는 연동 구조 완성 (github.com/justinnn980/SAP)

OData Spring Data JPA PostgreSQL Docker Compose
