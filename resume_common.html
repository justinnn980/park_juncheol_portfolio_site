Summary
한눈에 보는 요약
실서비스 OTT 앱 "오초이스"를 1년 10개월간 Flutter로 단독 개발/운영했습니다. LG헬로비전(가입자 343만 명)과 딜라이브(매출 3,500억) 두 파트너사의 앱을 하나로 통합하는 마이그레이션 2건을 기획부터 배포까지 주도했고, 상태관리 구조 재설계 / DRM 통합 / 성능 최적화로 로딩 속도 39% 개선을 이뤘습니다. iOS/Android 정식 출시와 버전 관리를 직접 담당했으며, 개인 프로젝트에서도 기획부터 배포까지 Flutter 앱을 단독으로 완성해온 경험이 있습니다.
Section 01
실서비스에서 해결한 문제들
PROBLEM 01
셋톱박스 3대 페어링 상태 — 연결 / 기기 / 콘텐츠 단위 분리
최대 3대 기기 상태 혼재 → Riverpod으로 상태 단위 분리 → 상태 변화 즉시 반영
셋톱박스 최대 3대 페어링 상태를 단일 Provider로 관리하다 발생한 상태 혼재/렌더링 오류를, 연결 상태 / 기기 노출 / 콘텐츠 접근 권한을 별도 Provider로 분리해 해결했습니다.
PROBLEM 02
쇼츠형 화면 오디오 이중 출력 — 플레이어 생명주기 분리
스크롤 시 이전 영상 오디오 잔존 → 재생 라이브러리 소스 레벨 분석 → 오디오 겹침 완전 해결
쇼츠형 피드 스크롤 시 발생한 오디오 겹침 문제를 재생 라이브러리 소스 코드까지 직접 분석해, 플레이어 생성/재생/종료 단계를 명시적으로 분리 호출하도록 수정해 해결했습니다.
PROBLEM 03
NCG DRM → Multi DRM 전환 — 단일 플레이어로 통합
파트너사마다 다른 DRM 방식 → DRM 추상화 인터페이스 설계 → 서비스 무관 동일 시청 경험
딜라이브(NCG DRM)와 헬로tv(Multi DRM) 사이의 DRM 방식 차이를, DRM 타입을 내부에서 분기 처리하는 단일 플레이어 인터페이스로 추상화해 통합했습니다.
PROBLEM 04
Flutter 2 → 3 메이저 버전업 — 전체 의존성 재검토
Null Safety 전환 필요 → DRM/플레이어/상태관리 의존성 전체 검토 → 무중단 업그레이드 완료
Flutter 2 기반 코드를 3으로 업그레이드하며 연결된 모든 라이브러리의 호환 버전을 재검토하고 Null Safety 마이그레이션이 필요한 코드를 직접 수정해 무중단으로 전환했습니다.
PROBLEM 05
WebView + JS Bridge — 로딩 속도 39% 단축
앱 배포 주기 의존 + 초기 로딩 지연 → JS Bridge 양방향 통신 구조 설계 → FCP −39% / 즉시 반영 운영 구조
콘텐츠가 자주 바뀌는 탐색 화면을 웹으로 분리하고 Flutter ↔ WebView JS Bridge 구조를 설계해, 로딩 속도를 39% 단축하고 앱 재배포 없이 콘텐츠를 즉시 반영할 수 있게 만들었습니다.
변경 전
탐색 화면 변경 → 앱 코드 수정 → 빌드 → 앱스토어 심사(1~3일) → 배포
변경 후
탐색 화면 변경 → 웹 배포 → 즉시 반영 (앱 배포 없음)
