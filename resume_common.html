Section 02
실제로 해결한 문제들
문제 01
기기 3대를 연결해 쓸 때 화면이 꼬이는 문제
여러 기기 상태가 뒤섞임 → 기기별로 상태를 따로 나눠서 관리 → 상태 변화가 바로바로 정확히 반영
하나의 앱에서 최대 3개의 기기를 연결해 쓸 수 있는 서비스에서, 기기 상태를 하나로 묶어 관리하다 보니 화면이 꼬이거나 잘못 표시되는 문제가 있었습니다. 기기 연결 상태, 화면 표시, 콘텐츠 접근 권한을 각각 따로 관리하는 구조로 바꿔 문제를 해결했습니다.
문제 02
영상을 넘길 때 소리가 겹쳐서 들리는 문제
화면을 넘기면 이전 소리가 남아있음 → 사용 중인 재생 프로그램 내부까지 직접 분석 → 소리 겹침 문제 완전히 해결
짧은 영상을 연속으로 넘겨보는 화면에서, 이전 영상 소리가 다음 영상과 겹쳐 들리는 문제가 있었습니다. 안내 문서만으로는 원인을 찾을 수 없어 사용 중인 재생 프로그램의 내부 동작 방식을 직접 분석해, 영상이 시작되고 끝나는 순서를 명확히 나눠 처리하도록 고쳤습니다.
문제 03
서로 다른 두 회사의 저작권 보호 방식을 하나로 통합
회사마다 저작권 보호 방식이 다름 → 공통으로 쓸 수 있는 구조로 설계 → 어느 회사 콘텐츠든 동일한 화면으로 시청
두 파트너 회사의 영상 저작권 보호 방식이 서로 달라 하나의 앱으로 합치기 어려운 상황이었습니다. 두 방식을 모두 처리할 수 있는 공통 구조를 설계해, 사용자 입장에서는 어느 회사의 콘텐츠든 차이 없이 동일하게 볼 수 있도록 만들었습니다.
문제 04
앱을 큰 폭으로 업그레이드할 때 문제없이 전환
앱 개발 도구의 대규모 업그레이드 → 연결된 모든 기능을 하나씩 재점검 → 오류 없이 안정적으로 전환 완료
앱을 만드는 데 쓰는 도구가 크게 업그레이드되면서, 앱에 연결된 여러 기능이 한꺼번에 영향을 받을 수 있는 상황이었습니다. 재생, 저작권 보호, 화면 상태 관리 등 연결된 기능을 하나씩 다시 점검해, 문제 없이 안정적으로 업그레이드를 완료했습니다.
문제 05
화면 로딩이 느려 사용자가 이탈하는 문제
앱 업데이트를 해야만 화면을 바꿀 수 있음 + 로딩 지연 → 해당 화면을 별도로 분리해 구조 개선 → 로딩 속도 39% 개선 / 업데이트 없이 즉시 반영
콘텐츠가 자주 바뀌는 화면인데도, 내용을 바꾸려면 매번 앱 업데이트와 심사를 거쳐야 하고 로딩도 느려 사용자가 이탈하는 문제가 있었습니다. 해당 화면을 앱과 실시간으로 연결되는 별도 구조로 분리해, 로딩 속도를 39% 개선하고 이후로는 앱 업데이트 없이 화면 내용을 바로 반영할 수 있게 만들었습니다.
이전 방식
화면 내용 변경 → 앱 코드 수정 → 심사 신청(1~3일 대기) → 배포
개선 후
화면 내용 변경 → 바로 반영 (앱 업데이트 불필요)
